픽AI(PICKAI) · 토스 앱 (앱인토스)

개인정보처리방침

시행일: 2026년 10월 11일 (최초 공개 게시일)
서비스명: 픽AI(PICKAI) · 개인정보처리자(상호): 코드
적용 대상: 토스 앱 내 「픽AI(PICKAI)」 미니앱(앱 이름 pickai) 및 연결된 토스 전용 API

Google Play용 픽AI의 개인정보처리방침과 별도입니다. Google·Naver 로그인·Google Play 결제는 토스 픽AI에서 사용하지 않습니다.

1. 개인정보의 처리 목적

픽AI 토스 미니앱(이하 「서비스」)은 다음 목적을 위해 개인정보를 처리합니다.

  • 토스 로그인 연동·회원 식별·세션 유지
  • 주식·시세 정보 조회, 관심종목·분석 기록 등 서비스 제공
  • 차트·종목 AI 분석, 오늘의 PICK·투자 부적 등 기능 제공(해당 기능 이용 시)
  • 포인트·멤버십·유료 기능 운영(실제 연동·제공 시)
  • 문의 대응, 보안·부정 이용 방지, 서비스 개선

2. 처리하는 개인정보 항목

아래는 현재 코드·구현에서 확인된 처리를 바탕으로 한 목록입니다. 실제 수집 범위는 토스·앱인토스 정책 및 기능 제공 여부에 따라 달라질 수 있습니다.

2.1 토스 로그인·인증

  • 앱(WebView): 토스 로그인 후 서버 교환 결과로 Supabase Auth access_token, refresh_token, 앱인토스 userKey(숫자)를 WebView localStorage에 저장합니다 (키: pickai.intoss.toss_session.v1). 미니앱을 다시 열었을 때 로그인 상태를 복원하는 데 사용됩니다.
  • 로그인 요청(앱 → Supabase Edge Function exchange-toss-auth): 토스에서 받은 authorizationCode, referrer(예: DEFAULT/SANDBOX), CSRF 방지용 state를 JSON으로 전송합니다. 코드·토큰은 공개 문서에 기재하지 않습니다.
  • Edge Function → 토스 API: 인가 코드로 토스 파트너 API를 호출하고, 로그인 사용자 userKey를 확인합니다(mTLS는 서버에만 보관).
  • Supabase Auth: userKey 기반 내부용 synthetic 이메일 형식 (appsintoss+{userKey}@users.internal.pickai — 실제 메일 발송 없음), 사용자 메타데이터 apps_in_toss_user_key, auth_via: apps_in_toss, pickai_app: pickai로 Auth 사용자·세션을 발급합니다.
  • 토스 전용 API GET /auth/me(Bearer = Supabase access JWT): SQLite 사용자 정보(내부 ID, synthetic 이메일, 닉네임, 플랜 등), 포인트 지갑·멤버십 요약, 연동된 소셜 계정 목록(토스 로그인만 사용 시 Google/Naver 연동 없음)을 반환합니다. Google·Naver 로그인 API는 토스 서버 프로필에서 사용하지 않습니다.
  • 토스 파트너 API login-me: 앱·Edge Function 코드 기준 응답 필드는 userKey(숫자)와 선택적 scope입니다. 이 경로로 실명·휴대전화·토스 계정 이메일을 앱에 표시하거나 토스 전용 API SQLite에 저장하는 구현은 없습니다.
  • 앱 UI(WebView): 로그인 후 MY·홈 등 화면에 앱인토스 userKey를 표시할 수 있습니다(예: 「회원 {userKey}」). @apps-in-toss/web-framework의 TossAuth.login()으로 인가 코드·referrer를 받고, 위 Edge Function으로 교환합니다.
  • 토스·앱인토스 SDK: 공식 문서·플랫폼 정책에 따라 로그인·WebView 환경에서 추가 정보가 제공될 수 있습니다. 위 항목은 현재 앱·서버 구현에서 확인된 범위입니다.

Google·Naver 소셜 로그인 비밀번호는 수집·저장하지 않습니다.

2.2 토스 전용 API 서버(로그인 후, 기능 연동 시)

Bearer 토큰(Supabase access JWT)으로 인증된 요청 시, 서버 SQLite 등에 다음이 저장·조회될 수 있습니다.

  • 내부 사용자 ID(Supabase sub와 연동), synthetic 이메일, 표시 닉네임(기본값 「Toss 사용자」로 생성되는 구현 존재)
  • 포인트 지갑·포인트 거래·포인트 예약(AI 유료 분석 등)
  • 관심종목(/user/favorites), AI 분석 기록(/analysis-history) — API 연동·동기화 시
  • 차트·전망·부적·오늘의 PICK 등 — 해당 API가 출시 범위에서 활성화·이용된 경우
  • 투자 부적: 생성 요청·생성 이미지·상태 — 해당 기능 이용 시

결제: 현재 토스 픽AI 앱·서버에서는 Google Play 결제 검증 및 앱인토스·토스페이 결제 연동이 제공되지 않는 구성일 수 있어, 결제 거래·주문 식별자는 저장하지 않습니다. 결제 연동 후 수집 항목은 별도 고지합니다.

2.3 기기(브라우저) 로컬 저장

서버 동기화 전·실패 시 로컬에만 남을 수 있는 데이터(앱 구현):

  • localStorage: 로그인 세션(access·refresh 토큰, userKey), 차트 AI 분석 기록·결과, 전망 분석 기록, 투자 부적 목록, 관심종목(로컬), 최근 본 종목, 종목 디렉터리 캐시, 언어 설정 등
  • sessionStorage: 로그인 진행 중 일시적 OAuth state, 로그인 후 복귀 경로 등(로그인 완료·취소 후 제거)

2.4 차트·AI 분석

  • 이용자가 선택한 차트 이미지, 종목·시장·봉 주기 등 분석에 필요한 정보가 서버를 경유해 AI API로 전송될 수 있습니다.
  • 종목 전망·텍스트 AI 분석: 종목 코드·시세·지표 등 시장 데이터가 분석에 사용될 수 있습니다.
  • 토스 전용 API의 차트·AI 분석 요청 구성상, OpenAI 등에 전달하는 프롬프트·메시지 본문에 이용자 이메일·세션 토큰·결제 정보를 넣지 않도록 구현되어 있습니다. 다만 서버 운영 로그에는 내부 사용자 ID 등이 기록될 수 있습니다(§2.5).

2.5 자동 생성·로그

  • 접속 일시, IP 주소, 요청 경로, 오류·보안 로그 — 토스 전용 API 서버·Supabase·Edge·호스팅(PM2 등) 운영 로그
  • 일부 기능(예: 차트 AI 분석) 서버 로그에 내부 사용자 ID가 포함될 수 있습니다.
  • 코드베이스에 로그 보관 기간·자동 파기·접근 RBAC를 정의한 설정은 없습니다(호스팅·PM2·Supabase 대시보드 정책은 별도).

2.6 Google Play 앱에서만 해당(토스 픽AI 해당 없음)

  • Google/Naver 소셜 프로필, Google Play 구매 토큰, installationId 기반 웰컴 포인트(토스 로그인 exchange에는 현재 미전송)

3. 보유 및 파기

원칙적으로 회원 탈퇴(계정 삭제) 시 서버에 저장된 해당 이용자 데이터를 삭제합니다. 자세한 항목은 계정 삭제 안내를 참고하세요.

계정 삭제 시 토스 전용 API는 SQLite 사용자·연관 데이터를 삭제하고, 삭제 작업 상태를 account_deletion_jobs에 기록합니다. 서버 설정이 활성화된 경우 Supabase Auth 사용자도 삭제합니다. 탈퇴 진행·완료 상태에서는 동일 JWT로 서버에 사용자 행이 재생성되지 않도록 차단합니다.

현재 운영(2026-10-10 읽기 전용 점검): Supabase Auth 삭제 게이트가 비활성이면 계정 삭제 API는 서버 데이터를 삭제하지 않고 오류로 종료됩니다. 게이트 활성화 후에는 위 절·계정 삭제 안내의 흐름을 따릅니다.

토스 로그인 경로에서는 Google 앱의 installationId 기반 웰컴 포인트·exchange 시 웰컴 지급 호출이 적용되지 않습니다. 탈퇴 시 소셜 연동이 없고 google_sub가 pickai:toss: 형태인 사용자에 대해서는 웰컴 중복 방지용 social claim 백필을 하지 않습니다.

보유·파기: 회원 탈퇴 성공 시 서버 SQLite 연관 데이터 삭제(세부는 계정 삭제 안내). 법령상 의무 보관·분쟁·부정 이용 방지·백업·운영 로그(내부 사용자 ID 포함 가능, §2.5)의 보관 기간·접근·파기는 앱 코드에 상세 기간이 정의되어 있지 않으며, 호스팅·Supabase 등 운영 환경 정책에 따릅니다.

로컬 저장 데이터는 로그아웃 시 로그인 세션(localStorage)이 제거되고, 앱 삭제·브라우저 데이터 삭제 시 기타 로컬 데이터가 제거될 수 있습니다. 과거 버전에서 남은 세션 정보는 최초 읽기 시 localStorage로 이전될 수 있습니다.

4. 제3자 제공

이용자 동의 또는 법령에 따른 경우를 제외하고 개인정보를 제3자에게 판매하거나 제공하지 않습니다.

법령에서 정한 경우(통계·과학적 연구 등 법령이 허용하는 범위)에는 개인정보를 제공할 수 있으며, 그 범위와 절차는 관련 법령을 따릅니다.

5. 처리 위탁·제공받는 자(연동)

서비스 제공을 위해 다음과 같은 외부 서비스를 이용할 수 있습니다.

아래 목록은 서비스 운영에서 이용하는 연동 수단입니다. 수탁자별 위탁 업무·재위탁·이용자 고지 방식은 계약 및 관련 법령에 따라 본 절을 업데이트할 수 있습니다. 앱 번들에는 Supabase 관리자 키·토스 mTLS 개인키를 포함하지 않습니다(Edge·서버 전용).

  • 토스(앱인토스)·토스 파트너 API: 로그인·userKey 확인
  • Supabase: Auth(세션 JWT), Edge Function(코드 교환) — 프로젝트: PICKAI 전용 ref 운영
  • 토스 픽AI API 서버: 시세·AI·포인트·기록 등 (별도 호스트)
  • 금융·시세 데이터 제공자: 종목·시세 조회
  • OpenAI 등 AI API: 차트·종목 AI 분석
  • 클라우드·호스팅: API·DB 운영
  • 토스 결제(앱인토스·토스페이): 현재 미연동 — 연동 시 별도 고지

6. 국외 이전

OpenAI(차트·AI 분석), Supabase(Auth·Edge Function), VPS 호스팅(토스 전용 API), 토스 파트너 API 등 일부 처리는 국외에서 진행될 수 있습니다. 처리 국가·리전·이전 항목·보유 기간·동의·거부 방법은 제공자·계약·대시보드 설정에 따라 달라질 수 있으며, 변경 시 본 방침을 통해 안내할 수 있습니다.
